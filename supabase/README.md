## Images

Existing originals remain in `images/`. `npm run images:optimize` produces WebP display versions and 320-pixel thumbnails under `images/optimized/`. Public HTML/CSS/catalogue use those files. The build excludes source PNGs and superseded videos. Logos remain original PNGs to preserve their SVG mask behavior. The active hero video is unchanged.

Admin automatically decodes and re-encodes JPEG/PNG/WebP photos locally. Input limit: 15 MB / 40 megapixels. Output: maximum 1200-pixel longest edge, <=450 KiB full image; maximum 320-pixel thumbnail, <=64 KiB. Aspect ratio and transparency are preserved; metadata is stripped by the canvas. Unsupported/corrupt images fail before upload. WebP conversion must succeed; it never silently uploads an uncompressed original.

The `product-images` bucket allows only WebP, maximum 512 KiB per object, with writes restricted to verified admin membership. Files use unique revision names and immutable cache headers. MIME/byte limits are enforced by Storage; browser dimensions/compression are a normal-upload guarantee, not protection from a malicious authorized admin. Product photos are public by URL, including draft photos; never use this bucket for private documents. Product metadata for drafts/archives remains protected by RLS.

Old image versions are retained so concurrent users do not see broken images. An upload followed by a failed/ambiguous save can leave an unreferenced image; clean up only after checking all database references. Do not delete an upload merely because a database response timed out.

## Catalogue behavior

`data/products.json` is the authoritative local seed. Build generates static catalogue HTML, request options, catalog-data.js and SQL seed from it. Live mode replaces the public data from Supabase before initial interactions and React sections mount; all views use the same returned products. New products default to draft and not featured. The owner explicitly chooses homepage positions. Reload/open the collection to see changes; no realtime session replacement discards customer input.

If live fetching fails, the site does not silently show obsolete local products as available. It shows an error and still permits a custom enquiry. Empty live catalogues stay empty. Database unique names prevent ambiguity in the existing name-valued request selectors. Stable immutable product IDs preserve shared links and future backend validation.
